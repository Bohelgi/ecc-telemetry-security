# Підключення нового пристрою

Захист не залежить від типу даних: шифруються довільні байти, а опис того, що саме вимірює пристрій, винесено в профіль. Тому новий пристрій додається без змін у коді шлюзу.

## 1. Профіль пристрою

Вбудовані профілі: `power-meter`, `smart-plug`, `climate-sensor`, `smart-lamp`, `door-sensor`.

Власний профіль описується текстовим файлом (`--profiles profiles.txt` і для шлюзу, і для пристрою):

```
profile water-meter Лічильник_води
field flow Витрата л/хв 0 200
field leak Витік =Немає/Є 0 1
```

Рядок `field`: ім'я, підпис, одиниця, мінімум, максимум. Підкреслення в підписах замінюються пробілами, `-` означає відсутність одиниці, одиниця виду `=Вимк/Увімк` робить поле станом (вкл/викл).

Шлюз відхиляє значення поза діапазоном, неправильну кількість полів і дані чужого профілю.

## 2. Реєстрація пристрою

```
device_simulator --id lamp-hall --profile smart-lamp --key-file lamp-hall.hex --export-identity trust_store.txt
```

Команда створює ключ пристрою й дописує у довірений список рядок `id відкритий_ключ профіль`. Профіль прив'язаний до ідентичності: пристрій не може видати себе за інший тип.

## 3. Джерело даних

Шифрувальна частина однакова для симулятора й реального приладу, змінюється лише джерело значень.

- `--source sim` (за замовчуванням): вбудований симулятор профілю.
- `--source stdin`: значення читаються з стандартного входу, по одному рядку на вимірювання, у порядку полів профілю.

```
my_sensor_reader | device_simulator --id meter-02 --profile power-meter --source stdin --transport http --port 6020
```

Будь-яка програма, що друкує числа (читання послідовного порту, опитування Modbus, MQTT, скрипт), стає захищеним пристроєм без змін у криптографічній частині.

## 4. Код на боці пристрою

```cpp
telemetry::DeviceAgent agent("lamp-hall", telemetry::EccIdentity::loadOrCreate("lamp-hall.hex"));
telemetry::HelloMessage reply = transport.exchangeHello(agent.buildHello());
agent.completeHandshake(reply);

telemetry::Reading reading;
reading.unixTimestampMs = nowMs();
reading.profileId = "smart-lamp";
reading.values = {1.0f, 80.0f, 8.0f};
transport.send(agent.protect(reading));
```

## 5. Перегляд

Шлюз віддає `/api/devices`, `/api/profiles`, `/api/readings`, `/api/events`. Сторінка панелі малює плитки й графіки за профілем, тому новий пристрій з'являється без змін у фронтенді. Старий `/api/telemetry` (U, I, P, T лічильника) збережено.

Запуск п'яти демонстраційних пристроїв разом із шлюзом: `scripts\demo_fleet.ps1`.

## Обмеження

- Шлюз по TCP обслуговує одного клієнта за раз; для кількох пристроїв одночасно використовуйте `--transport http`.
- Бібліотеку перевірено на ПК (MSVC, Mbed TLS 2.28); для ESP32 потрібна збірка як компонента ESP-IDF, HTTP-клієнт замість сокетів і захищене сховище ключа.
- Для закритих приладів (готова розетка, лампа) потрібна програма-посередник поряд із приладом; ділянка між приладом і посередником не захищена.
- Команди від шлюзу до пристрою, відкликання пристроїв і ротація ключів не реалізовані.
